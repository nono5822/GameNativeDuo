# 2026-10-20: Balatro dual-screen mod 0.2.0

Rewrite of `assets/duo/mods/balatro/GameNativeDuo-split` (Lovely mod, Balatro 1.0.1o). Design informed by
[rosbean/balatro-dualscreen](https://github.com/rosbean/balatro-dualscreen) (GPL-3.0, native LÖVE-on-Android port):
same idea of what goes where (hand, shop, packs, menus below; table above; hand info on the bottom; larger hand),
and two of its findings (the dead-pack `can_skip_booster` crash, tooltips opening off the panel). No code copied.

## Approach (why it is cheaper than the reference)

The reference renders the game twice (screen 1, then the screen-2 objects into an off-screen canvas), reads the
canvas back (`newImageData`, ~3.75 ms at full panel) and pushes the pixels over JNI every second frame. Here the
game draws one tall window and GameNative Duo shows each part on its screen: one render pass, no readback, no copy.
Objects really live in the bottom part (room coordinates below the room), so collision, touch, controller focus,
tooltips and every animation are vanilla's own.

- `duo_core.lua`: split from `layout.json` (fallback: 16:9 top part of a tall window), room <-> window mapping,
  bottom anchor, `room_h()` / `vanilla_y()` for vanilla's "on screen" checks.
- `duo_layout.lua`: hand (and so shop, blind select, cash out, packs, which vanilla hangs from the hand) on the
  bottom; consumables top right of the bottom; joker row widened and centred on top; play area lowered; discard off
  the bottom's right edge; menus that fit on the bottom; hand scaled 1.15 (width-fitted); play area parked on the
  bottom in shop / blind select / packs so packs burst where they are dealt.
- `duo_render.lua`: vanilla shaders recompiled with a per-screen remap (CRT per screen; background, splash and flash
  centred on the top screen and continued below at the bottom's pixel density); bottom background game / colour /
  image + dim; HUD clipped to the top screen; final composite as two quads (hidden corners never shaded).
- `duo_bridge.lua`: HELLO caps 0x2f, native touch into Balatro's own touch mode (no cursor), ui.json rules,
  elements.json (Hand, Consumables, Hand info, Menus).
- `duo_preview.lua`: "Hand info" box (hand name, level, chips x mult) reading the HUD's own values.

## Vanilla assumptions that broke, and the fix (all found on the device)

| Symptom | Cause | Fix |
|---|---|---|
| Nothing on the bottom screen reacted to touch | `Controller:get_cursor_collision` returns when the cursor is more than `DRAW_HASH_BUFF` below the room | bound -> `GNDuo.room_h()` |
| Controller focus / button shortcuts ignored bottom nodes | `is_node_focusable` (`T.y > ROOM.h + 3`), `process_registry` (`T.y < ROOM.h + 2`) | same |
| Booster pack cards never dealt (stay in the burst, face down) | `card.lua:1787` waits for `G.pack_cards.VT.y < ROOM.h` | `vanilla_y()` |
| Blind choices had no Select button | `blind_choice_handler` waits for `G.blind_select.VT.y < 10` | `vanilla_y()` |
| Tutorial shop step never started | `G.shop.VT.y < 5` | `vanilla_y()` |
| Blind select on the top screen | its offset is measured from the joker row, not the hand | `place_blind_select()` after vanilla's line, by its top (the box is 31 tiles tall) |
| HUD panel tail on the bottom screen | HUD is 30 tiles tall (runs off vanilla's window) | scissor to the top screen |
| Intro vortex / background centred on the hinge ("cropped" intro of the reference) | shaders use `love_ScreenSize` | per-screen remap |
| CRT curved the whole tall window | one pass over the canvas | two quads, `duo_rect` per screen |
| Main menu buttons (16.8 tiles) wider than the bottom | Discord/X/language column beside them | moved to a row under them, only when split |
| Menus re-anchored to the bottom landed on the top screen | `c`/`m` alignment measures `Mid`, stale for a few frames | re-align each frame until stable (max 30) |
| Run setup / options stayed on top | menu root is a 100x57 dimmer around the panel | measure the panel (`content_of`) |
| Pack burst on the top screen, cards below | packs and vouchers are drawn to `G.play` | `G.play` waits on the bottom (empty only) in shop / blind select / packs |
| Pack sparkles on the top screen | `attach = G.ROOM_ATTACH` | `pack_attach()` |
| Consumable tooltips opened onto the top screen | `align_h_popup` uses the room y | flips to below near the bottom screen's top |
| Room parallax tilted towards the bottom when touching it | eased cursor y | `vanilla_y()` |

## Long-run checklist (late game, stress-tested with a dev hook)

Tested on the Thor with 9 jokers (2 negative), 4/4 consumables, hand size 11, 4 shop slots, $500, every mega
pack, Run Info / Options / Deck, The Fish, The Hook, The House, controller only and touch only.

- Joker row: 9 jokers fit the widened row (13 tiles); vanilla overlap beyond that.
- Shop with 4 joker slots (Overstock Plus): 12.4 tiles, fits (bottom is 14.8).
- Cash out: list starts under the consumables (lift 1.1) and has room for ~14 rows.
- Packs: Arcana / Spectral show the hand (11 cards fanned) above the pack cards; tarots on hand cards work
  (World converted two cards, they flip back face up). Celestial, Standard (editions, glass), Buffoon: OK.
- Blind select: the on-deck column rises; placed 3.75 tiles down so its Select clears the consumables.
- Boss colours reach both screens; HUD blind panel on top.
- Hand drag-reorder and hold-for-tooltip by touch: OK. Controller focus crosses screens (jokers -> Cash Out).
- Deck view (19 tiles) and the collection stay on the top screen (too wide): use the controller or top touch.

Open / not verified:
- Game over and win overlays not reached on the device (they go through `overlay_menu`, so they follow the menu
  rule when they fit).
- Top-screen taps go through GameNative's mouse (its touchscreen mode decides how); selling and reordering jokers
  by touch needs that or the controller.
- Balatro's own resolution / window mode settings: changing them breaks the split (the window no longer matches
  `layout.json`); leave them at fullscreen.
- Hand scale stays 1.15 with very large hands (vanilla overlap, a bit more of it).

## Performance (Thor, Zink on Turnip, vsync on)

Late game (9 jokers): 43 fps at 1920x2160. Lua time 10.4 ms/frame (update 5.1, draw 5.3); `love.graphics.present`
12.8 ms with vsync on or off. Bottom background as solid colour: 44.8 fps; CRT off: 43.4. So the cost is the frame's
present path, which scales with the window: 7.8 ms at 75% (1440x1620) and 57-60 fps. The mod defaults Balatro to 75%
(`DuoGameMod.splitScale`; the user can pick 100% in the GameNative Duo tab). Our own per-frame cost: layout 2.8 µs,
hand info 1.3 µs, bridge poll 58 µs (one recvfrom through Wine).

## App changes

- `DuoModCatalog`: Balatro uses the NATIVE split and `splitScale = 0.75`; the mod folder is installed whole.
- `DuoModInstaller`: optional per-mod split scale (restored on disable); an app update migrates a container whose
  bundled mod changed split layout (FILL -> NATIVE), unless the user changed the screen size.
- `SplitScreenController`: a NATIVE container whose X screen is not the native size is cut like FILL instead of not
  at all (that migration's first session, hand-edited sizes).
- `UiLayoutEditor`: keeps asking the mod for its element list (GameNative pauses the game while its menu is open).

## Testing notes (for whoever continues)

- A dev-only Lovely mod (not in the APK) ran Lua from `%AppData%/GameNativeDuo/dev-cmd.lua`. It must set
  `G.F_NO_ACHIEVEMENTS = true` and make runs seeded first: GameNative uploads achievements to Steam in real time
  (one, "Nest Egg", was earned this way before the guard existed), and unlocks change the profile.
- Back up `%AppData%/Balatro/{settings.jkr,1,2,3}` before testing and restore it after.
