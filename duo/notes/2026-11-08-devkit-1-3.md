# Devkit items 1-3: Bridge v2 + SDKs, dev tools, game profiles

User asked (2026-11-08) for items 1-3 of `duo/docs/devkit-platform.md`, in that order. Work survives a plan limit:
every checklist box is one commit; a new session reads this file and starts at the first unchecked box.

- Worktree `~/dev/GameNativeDuo-uniform`, branch `duo/devkit-sdk` (from `duo/uniform-editing`, unmerged). Nothing pushed.
- The main checkout (`~/dev/GameNativeDuo`) holds uncommitted hotkeys work: never commit, reset or copy it.
  It already contains the app side of `COMMAND`/`COMMAND_RESULT` (0x05/0x85, caps 64/128 named) and key injection
  through the X server (`hotkeys/HotkeyInput.kt`). This branch therefore does **not** build those two rows of the
  Bridge v2 table app-side; it uses the same wire numbers so the merge is mechanical. The SDKs implement the mod side
  of COMMAND.
- SDK code is shared **as source** (`duo/sdk/csharp/GameNativeDuo.Sdk/*.cs`, `<Compile Include>` in each adapter,
  `DUO_SDK_EMBEDDED` makes types internal): the bundled mods stay one DLL each, and two plugins in one game cannot
  clash. The NuGet build of the same files is public, multi-targets `net46;netstandard2.0`.
